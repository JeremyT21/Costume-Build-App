# Cospal Agents

Cospal uses seven specialist agents coordinated by an orchestrator. Each one is a real
agent: an LLM that **decides which tools to call, observes the results, and revises its
own work** until a validator accepts it. None of them is a single prompt-and-parse call.

## Why these jobs need agents

The OpenAI *Practical Guide to Building Agents* [1] says agents earn their place where
deterministic code falls short, and names three signals:

| Signal from the guide [1] | Where it shows up in Cospal |
| --- | --- |
| **Complex decision-making**: nuanced judgment and context | Buy vs. build vs. print vs. sew depends on budget, skill, look, and size together |
| **Difficult-to-maintain rules**: rulesets that grow unwieldy | Every character, material, and product is different; rules cannot enumerate them |
| **Heavy reliance on unstructured data**: images and free text | Character art, product reviews, and photos of the user's own build |

The guide also defines an agent as a system that "leverages an LLM to manage workflow
execution and make decisions", "recognizes when a workflow is complete and can
proactively correct its actions", and uses tools [1]. Every agent below meets that bar.

LangGraph's *Workflows and Agents* guide [2] separates fixed workflows ("predetermined
code paths") from agents ("dynamic and define their own processes and tool usage").
Cospal's orchestrator is a workflow; the specialists inside it are agents. It also
names the two patterns Cospal relies on most: **orchestrator-worker** and
**evaluator-optimizer** [2].

## Pattern map

```
                      ┌──────────────── Orchestrator (workflow) ───────────────┐
 images ──► Concept agent ──► Component agent ──► Fabrication agent ──► user picks concept
                                                                              │
                                              ┌───────────────────────────────┤ fan-out (parallel)
                                              ▼                               ▼
                                     Modeling agent                    Shopping agent
                                  (render ⇄ critique loop)          ──delegates──► Sizing agent
                                              │
                                    later: Improvement agent (photo critique)
```

## The agents

Each agent is built with Pydantic AI [3]: typed dependencies, tools the model chooses to
call, a structured output type, and an **output validator** that raises `ModelRetry` to
send the agent back to work when its answer breaks a rule [4].

### 1. Concept agent (`app/agents/concept_agent.py`)
- **Job:** group uploaded images into up to 3 distinct costume versions and rank them.
- **Tools:** `zoom_image` crops any region and returns it as an image for closer study.
- **Self-check:** every image must belong to exactly one concept; missing or duplicated
  indexes trigger a retry with the exact problem listed.

### 2. Component agent (`app/agents/component_agent.py`)
- **Job:** break the character into components and separate skin finishes (body paint,
  makeup) from pieces that must be made or bought.
- **Tools:** `zoom_image` for small details (buckles, trims, emblems); `lookup_part` to
  align a part with known types, body zones, and 3D templates.
- **Self-check:** rejects duplicates, a body-paint item marked as fabricated (or the
  reverse), and suspiciously short lists.

### 3. Fabrication agent (`app/agents/fabrication_agent.py`)
- **Job:** choose buy or build, and the method, cost, materials, and steps for each part.
- **Tools:** `get_budget`, `estimate_3d_print` (builds the real body-scaled mesh and
  reports size, filament, cost, print hours), `fabric_needed` (drafts the real pattern
  and measures yardage), `material_price`, `amazon_price_check`.
- **Self-check:** every component planned; only methods the maker allowed; buy and
  printable flags consistent; **total within the budget tier**. When it runs over, it
  is told the exact overage and re-plans.

### 4. Modeling agent (`app/agents/modeling_agent.py`), evaluator-optimizer loop
- **Job:** design a printable 3D part that matches the character.
- **Tools:** `list_templates`; `render_preview` builds the mesh **at the wearer's size**
  and returns a shaded render image plus print stats. The agent compares the render
  with the reference art, changes parameters, and renders again.
- **Self-check:** it cannot finish without rendering at least once, and the final
  template must be one it actually rendered.
- **Geometry** is generated by code (`app/services/templates3d.py`), never invented by
  the LLM, so every STL is watertight and dimensionally correct.

### 5. Shopping agent (`app/agents/shopping_agent.py`)
- **Job:** find up to 3 Amazon products that match the component and budget.
- **Tools:** `search_products` (it refines queries when results miss); `check_fit`
  **delegates to the sizing agent** [5].
- **Self-check:** recommended URLs must come from real search results, so it cannot
  invent products.

### 6. Sizing agent (`app/agents/sizing_agent.py`)
- **Job:** read reviews ("runs small", reviewer height and build) and pick a size.
- **Tools:** `get_measurements`, `read_reviews`.
- **Runs as a delegate** of the shopping agent, sharing its usage budget [5].

### 7. Improvement agent (`app/agents/improvement_agent.py`)
- **Job:** critique the maker's finished piece against the character reference.
- **Tools:** `zoom_image` across reference and build photos; `technique_library`.

## Safety rails

- **Usage limits:** every run is capped at 16 model requests and 24 tool calls
  (`app/agents/llm.py`).
- **Graceful fallback:** if no model is configured or a provider call fails, each agent
  falls back to deterministic rules (`app/agents/heuristics.py`), so the app stays usable.
- **Grounding:** prices, sizes, and products come from tools, not model memory.

## Proof they work

`backend/tests/test_agents.py` drives each agent through Pydantic AI's `FunctionModel`
[6]. The model's choices are scripted, but **real tools, real validators, and the real
retry loop** run:

| Test | What it proves |
| --- | --- |
| `test_modeling_agent_must_render_then_sees_its_render` | Validator forces a render; the render image is returned to the model; the mesh is sized to the wearer |
| `test_fabrication_agent_replans_when_over_budget` | Tool results feed the plan; an over-budget plan is rejected and replaced |
| `test_fabrication_agent_rejects_disallowed_methods` | The maker's method preferences are enforced |
| `test_component_agent_fixes_skin_classification` | A misclassified body-paint item is corrected after a retry |
| `test_shopping_agent_delegates_fit_and_rejects_invented_urls` | Delegation to the sizing agent works; invented URLs are rejected |

Run them with `pytest backend/tests/test_agents.py -v`.
